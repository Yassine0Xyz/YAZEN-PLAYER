# Echo — Hybrid Music Player Foundation

Echo is a modular Flutter foundation for a high-performance hybrid music player that combines on-device audio with direct YouTube audio streaming. The project is designed for Android and iOS first, with the UI and service boundaries kept portable for future desktop support.

## Requirements

Use the Flutter stable channel. The project was prepared against the current Flutter 3.47 stable line and Dart SDK 3.7 or newer. The current dependency constraints are recorded in `pubspec.yaml`.

```bash
flutter pub get
flutter analyze
flutter run
```

The sandbox used to prepare this codebase did not contain a Flutter SDK, so device builds were not executed here. Run the commands above from a Flutter development environment after adding the platform project files generated by `flutter create .`.

`MediaTrack` is the domain boundary between local and online content. `MediaLibraryService` owns `on_audio_query` access and permission checks. `YoutubeService` is the typed, API-key-free boundary around `youtube_explode_dart` for search, metadata, and fresh audio-only stream URLs. `HybridAudioHandler` owns `just_audio`, `audio_service`, queue metadata, background controls, cache fallback, and delegates all YouTube extraction to `YoutubeService`. `HybridMusicController` exposes a small UI-facing state API through `ChangeNotifier`.

### Android

Add these permissions to `android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.WAKE_LOCK" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" android:maxSdkVersion="32" />
<uses-permission android:name="android.permission.READ_MEDIA_AUDIO" />
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.CHANGE_WIFI_MULTICAST_STATE" />
```

Inside `<application>`, use an audio-service-compatible activity and register the background service and media-button receiver. A generated Flutter project's `MainActivity` can extend `AudioServiceActivity` as described by the `audio_service` package documentation, or the manifest can point to the plugin activity for the simplest shell.

The repository includes `android/app/src/main/res/raw/keep.xml` to protect notification resources during release shrinking. Android 13 and newer use `READ_MEDIA_AUDIO`; Android 12 and older use `READ_EXTERNAL_STORAGE`.

### iOS

Add the following keys to `ios/Runner/Info.plist`:

```xml
<key>NSAppleMusicUsageDescription</key>
<string>Echo needs access to your media library to play local music.</string>
<key>NSLocalNetworkUsageDescription</key>
<string>Echo uses your local network to discover nearby listening parties.</string>
<key>NSBonjourServices</key>
<array>
    <string>_echo-party._tcp</string>
</array>
<key>UIBackgroundModes</key>
<array>
    <string>audio</string>
</array>
```

Enable the Background Modes capability in Xcode and select **Audio, AirPlay, and Picture in Picture**.

## Playback notes

YouTube audio URLs are temporary stream URLs. `YoutubeService` resolves them immediately before playback and uses `LockCachingAudioSource` to write audio bytes into an app-support cache keyed by stable video ID. Completed files are reused directly without contacting YouTube, while incomplete `.part` files are never treated as offline-complete. The extractor remains isolated behind the service boundary so it can later be replaced with a compliant provider, a backend proxy, or a first-party catalog without changing the UI.

`HybridAudioHandler.playTrack` starts a fresh one-item queue, while `addToQueue` resolves and appends a local or YouTube `AudioSource` without interrupting the active item. A parallel `MediaTrack` list keeps audio-service queue metadata aligned with just_audio's current index, including background next/previous controls. The Discover screen exposes **Instant Stream**, **Add to queue**, and **Download** actions through `HybridMusicController`.

`FullPlayerScreen` is a dedicated slide-up route. It listens to `audio_service` media and playback streams, renders a rotating artwork/vinyl centerpiece, and exposes seek, volume, shuffle, repeat, skip, and lyrics-panel controls. The shared `LyricsView` widget now owns the synced-line highlighting, auto-scroll, plain-text fallback, and bottom-sheet presentation used by the player.

`LocalPlaylistManager` persists custom playlists and favorites as compact JSON metadata through `SharedPreferences`. It stores stable local-file and YouTube identities, never audio bytes, and is exposed through `HybridMusicController`; local and YouTube track rows provide heart actions, while the Playlists tab supports creating and deleting custom playlists.

`YouTubeAudioCache` stores completed audio under the application support directory. It defaults to a 512 MB maximum and 30-day inactivity expiry, evicts least-recently-used completed files when the limit is exceeded, and protects the currently requested video from eviction. The service exposes `clear`, `clearAll`, `totalBytes`, and `prune` for settings and maintenance screens.

The initial UI implements the requested horizontal tabs and uses local songs for the local-library tabs. `HybridMusicController` already loads artists, albums, playlists, and derived folders so dedicated category screens can be added without changing the service boundary. YouTube search results populate the **Videos** tab.

For background playback, `audio_service` is initialized at app startup, while `just_audio` remains the actual playback engine. The handler broadcasts `MediaItem` and `PlaybackState` so lock-screen and notification controls have the same state source as the app UI.

## Killer features

The feature layer now includes four extensible capabilities. The AI mixer consumes a `StemSeparationResult` and starts one `just_audio` player per stem, with coordinated play, pause, seek, level control, and periodic drift correction. The stem service is intentionally separate from the mobile app because Demucs requires Python, PyTorch, model downloads, and considerably more memory than a mobile process should own.

| Feature | Main files | Integration boundary |
|---|---|---|
| AI stem separation | `stem_service/main.py`, `stem_service/requirements.txt`, `lib/services/stem_separation_service.dart`, `lib/screens/ai/ai_mixer_screen.dart` | Upload a mix to `/separate`, then pass returned stem URLs to `AiMixerScreen` |
| Synced lyrics | `lib/services/lyrics_service.dart`, `lib/screens/player/full_player_screen.dart` | Adjacent local `.lrc` files take priority; LRCLIB is used as a no-key fallback |
| EQ and 3D audio | `lib/screens/effects/equalizer_screen.dart`, `HybridAudioHandler` | Android EQ uses `just_audio`'s `AudioPipeline` and `AndroidEqualizer`; 3D invokes the optional `echo/audio_effects` native channel |
| Hybrid Party Mode | `lib/services/online_party_service.dart`, `lib/services/lan_party_service.dart`, `lib/screens/party/hybrid_party_screen.dart` | Online rooms use Pusher presence channels; Nearby rooms use NSD discovery plus TCP sockets with the same playback-state JSON |

### Running the backend services

The stem service is suitable for a Hugging Face Space or Replit deployment. From `stem_service/`, install `requirements.txt` and run `python main.py`; the process listens on the `PORT` environment variable and defaults to `7860`. Demucs downloads its model on first use, so a persistent model cache and an appropriate memory tier are recommended for deployment. The service accepts `POST /separate` as multipart field `audio` and returns a JSON object containing four downloadable URLs.

Party Mode no longer depends on a custom Python server. Online rooms use Pusher presence channels and client events; configure `PUSHER_CLUSTER`, `PUSHER_AUTH_ENDPOINT`, and the four real Pusher keys before shipping. The key array is a client-side selection mechanism, not a security boundary: Pusher app keys are public identifiers, while the presence-channel auth endpoint must protect access and production teams should confirm that key rotation complies with their Pusher plan and terms. Nearby rooms bind a local `ServerSocket`, advertise the port through NSD, and guests connect through `Socket` after automatic discovery. Android needs `INTERNET` and `CHANGE_WIFI_MULTICAST_STATE`; iOS needs `NSLocalNetworkUsageDescription` and the `_echo-party._tcp` Bonjour service declaration.

### Party synchronization protocol

Both transports use the same action-only `PartyActionEvent` JSON contract: `action`, `room_code`, `host_id`, `sender_id`, `track_id`, `title`, `position_ms`, `playing`, `timestamp_ms`, and `reason`. The only wire actions are `PLAY`, `PAUSE`, `SEEK`, `NEXT_TRACK`, `PREVIOUS_TRACK`, and `TRACK_CHANGE`. The host sends packets only after explicit handler actions, plus a single `SEEK` packet every 28 seconds as a lightweight correction anchor. Guests extrapolate playback locally from the event timestamp and their own clock; a local position listener corrects only when drift exceeds 1.5 seconds, with a three-second correction cooldown. Reconnects and the manual Resync control trigger an immediate correction without creating a continuous network stream. Pusher public client events are not suitable for this feature because they require a trusted server-side event publisher; the implementation therefore uses an authenticated presence channel and `client-party-action` events [10].

### Platform effects note

`just_audio` exposes a native Android equalizer pipeline, which is used by `HybridAudioHandler`. It does not expose a cross-platform virtualizer abstraction in this project version, so the 3D switch is an explicit method-channel boundary. Add the copy-ready Android bridge under `docs/android_virtualizer_bridge.kt` to bind Android's `Virtualizer` effect in a generated Android host. On iOS, replace that bridge with an `AVAudioUnit` spatial effect or a dedicated maintained audio-effects plugin.

## Theme and performance layer

`ThemeProvider` owns the active `EchoThemePreset`, immutable `ThemeTokens`, and an optional custom image provider. The included presets are `oled_black`, `rgb_rainbow`, `crimson_red`, and `pure_white`. The provider is mounted alongside `HybridMusicController`, so changing appearance does not recreate the audio handler or local-library service.

The RGB preset uses one `AnimationController` and one `CustomPainter` inside a `RepaintBoundary`. Only that painter repaints as the slow gradient moves; the rest of the Material widget tree does not rebuild every animation frame. The player visualizer follows the same pattern and stops its controller while paused. Pulsing play-button, mini-player, and status-dot effects are isolated in small stateful widgets and run only while active.

`ThemeBackdrop` provides the future custom-image-background boundary. When an image provider is supplied, it adds a tinted overlay and backdrop blur. Because blur is more expensive than a flat fill, the effect is opt-in and absent from the default OLED, RGB, crimson, and white presets.

The appearance sheet is available from the Home header through `showThemePicker(context)`, and the full `SettingsScreen` is available from the Home header for persisted theme, audio-effect, cache, notification, and playback preferences. The shared UI sources are also collected in `docs/ui_codeboxes.md` as direct-copy Markdown Dart codeboxes.

The Android shell includes `AudioServiceActivity`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, wake-lock, network, Wi-Fi, notification, and media-library permissions, plus the `com.ryanheise.audioservice.AudioService` service and media-button receiver. Copy the Android files into a generated Flutter project and run `flutter pub get` before building [15].

The final integration codeboxes are collected in `docs/final_polish_codeboxes.md`, including `SettingsScreen`, `LocalPlaylistManager`, `LyricsView`, the provider/bootstrap wiring, playlist-picker UI, and the Android XML/Kotlin configuration.

The daily-use layer now persists playback queue metadata and resume position, exposes a Queue screen with reorder/remove/clear/Play Next, and provides dedicated Favorites and Playlist Details screens. YouTube downloads support cancellation and partial-file cleanup; search uses bounded timeout/retry behavior. Audio focus and becoming-noisy events are handled explicitly, while sleep timer, playback speed, EQ, and surround preferences are applied through the handler. The pinned `just_audio` version does not expose a crossfade API, so crossfade remains an explicit future adapter rather than a misleading UI toggle.

Regression tests cover MediaTrack persistence, queue snapshot clamping, playlist/favorites persistence, and action-only party events. Run them with `flutter test` in a Flutter SDK environment.
